# Requirements Document

## Introduction

The TrustPause app helps users identify potential scams by analyzing input text (typed, pasted, or OCR-extracted from photos) and producing a risk assessment. Currently, the `inputSummary` field — displayed on the home screen preview and the full results page — is generated by naively truncating the first 100 characters of raw input text. This produces nonsensical summaries when OCR output starts with numbers or garbled text.

This feature introduces a `generateSubjectLine` function that uses the already-computed scam detection results (`scamType`, `redFlags`, `riskLevel`) to produce meaningful, descriptive subject lines. The function is a pure function requiring no external API calls, and the improved summaries flow automatically to all existing display surfaces.

## Glossary

- **Subject_Line_Generator**: The `generateSubjectLine` pure function that produces a human-readable subject line from analysis signals and input text
- **Analysis_Engine**: The existing `analyzeScamRisk` function that detects scam patterns and produces an `AnalysisResult`
- **ScamType**: An enumerated type identifying the category of scam detected (e.g., `bank_impersonation`, `grandparent_scam`, `unknown`)
- **RedFlag**: An enumerated type identifying a specific warning signal detected in the input (e.g., `urgency`, `gift_card`, `money_transfer`)
- **RiskLevel**: An enumerated type representing the overall risk assessment (`High Risk`, `Be Careful`, `Probably Safe`)
- **inputSummary**: The string field on `AnalysisResult` displayed as a preview on the home screen and results page
- **Entity_Descriptor**: A human-readable label derived from the `ScamType` (e.g., "Bank impersonation", "Family emergency scam")
- **Action_Descriptor**: A human-readable label derived from a `RedFlag` describing the scam tactic (e.g., "requesting money transfer", "asking for gift cards")
- **OCR_Noise**: Leading numeric characters, symbols, and whitespace commonly produced by optical character recognition of images
- **Display_Components**: The UI components that render `inputSummary` — the home screen banner, the results page risk banner, and the `ResultCard` component

## Requirements

### Requirement 1: Subject Line Generation from Scam Signals

**User Story:** As a user, I want the summary of my scam check to describe what was actually detected, so that I can quickly understand the nature of the threat at a glance.

#### Acceptance Criteria

1. WHEN the Analysis_Engine detects a known ScamType (not `unknown`), THE Subject_Line_Generator SHALL include the corresponding Entity_Descriptor in the subject line
2. WHEN the Analysis_Engine detects RedFlags that have Action_Descriptors, THE Subject_Line_Generator SHALL include up to two Action_Descriptors in the subject line
3. WHEN the Analysis_Engine detects a known ScamType and RedFlags with Action_Descriptors, THE Subject_Line_Generator SHALL combine the Entity_Descriptor and Action_Descriptors using an em dash separator
4. WHEN the ScamType is `unknown` and RedFlags with Action_Descriptors are present, THE Subject_Line_Generator SHALL prefix the subject line with "Suspicious message"

### Requirement 2: Fallback Text Extraction

**User Story:** As a user, I want a clean text excerpt as my summary when no scam is detected, so that I can still identify which message I checked.

#### Acceptance Criteria

1. WHEN the ScamType is `unknown` and no RedFlags are detected, THE Subject_Line_Generator SHALL extract a cleaned phrase from the input text
2. WHEN the input text contains OCR_Noise at the beginning, THE Subject_Line_Generator SHALL strip leading numeric characters, symbols, and whitespace before extracting the phrase
3. WHEN the input text contains newline characters, THE Subject_Line_Generator SHALL replace them with spaces and collapse consecutive whitespace into a single space
4. WHEN a sentence boundary is found within the first 100 characters of cleaned text, THE Subject_Line_Generator SHALL extract text up to and including that sentence boundary
5. WHEN the cleaned text exceeds 100 characters with no sentence boundary, THE Subject_Line_Generator SHALL truncate at the last word boundary before 100 characters and append an ellipsis

### Requirement 3: Output Constraints

**User Story:** As a user, I want subject lines that are consistently formatted and never empty, so that the display always looks correct.

#### Acceptance Criteria

1. THE Subject_Line_Generator SHALL return a non-empty string for all valid inputs
2. THE Subject_Line_Generator SHALL return a string with a maximum length of 120 characters
3. WHEN the generated subject line exceeds 120 characters, THE Subject_Line_Generator SHALL truncate it to 117 characters and append an ellipsis ("...")
4. THE Subject_Line_Generator SHALL return a string that contains no newline characters
5. THE Subject_Line_Generator SHALL produce the same output when called multiple times with identical inputs

### Requirement 4: Empty and Whitespace Input Handling

**User Story:** As a user, I want a clear indication when my input was empty, so that I understand why no analysis was performed.

#### Acceptance Criteria

1. WHEN the input text is empty or contains only whitespace and no scam signals are detected, THE Subject_Line_Generator SHALL return "Empty message"
2. WHEN OCR_Noise stripping removes all content from the input text, THE Subject_Line_Generator SHALL fall back to the original text with whitespace normalized rather than returning an empty result

### Requirement 5: Integration with Analysis Engine

**User Story:** As a user, I want the improved subject lines to appear automatically in my scam check results, so that I benefit from the improvement without any workflow changes.

#### Acceptance Criteria

1. WHEN the Analysis_Engine produces an AnalysisResult, THE Analysis_Engine SHALL use the Subject_Line_Generator to populate the inputSummary field instead of truncating the raw input text
2. THE Analysis_Engine SHALL pass the detected ScamType, RedFlags, RiskLevel, and input text to the Subject_Line_Generator

### Requirement 6: Consistent Display Across Surfaces

**User Story:** As a user, I want to see the same improved subject line on both the home screen preview and the full results page, so that the information is consistent everywhere.

#### Acceptance Criteria

1. WHEN a recent result is displayed on the home screen banner, THE Display_Components SHALL render the inputSummary from the AnalysisResult
2. WHEN a result is displayed on the results page risk banner, THE Display_Components SHALL render the same inputSummary from the AnalysisResult
3. WHEN a result is displayed in the ResultCard component, THE Display_Components SHALL render the same inputSummary from the AnalysisResult

### Requirement 7: Scam Type Label Coverage

**User Story:** As a developer, I want every ScamType to have a corresponding human-readable label, so that the subject line generator handles all scam categories.

#### Acceptance Criteria

1. THE Subject_Line_Generator SHALL define an Entity_Descriptor mapping for every value in the ScamType enumeration
2. WHEN a ScamType value has no matching Entity_Descriptor, THE Subject_Line_Generator SHALL treat it as equivalent to the `unknown` ScamType
